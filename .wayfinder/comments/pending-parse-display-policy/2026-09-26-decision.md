# Decision: what redisplay shows while a parse is pending

2026-09-26. **Self-adopted; the user confirmed it on 2026-09-26.**

Evidence: [research/treesit-tree-readers.md](../../research/treesit-tree-readers.md),
the [halt and resume contract](../ts-halt-resume-contract/2026-09-25-resolution.md),
and nemesis `2aea192dcd6` (`lisp/jit-lock.el`, `lisp/treesit.el`,
`src/treesit.c`).

## Terms

- A **pending parse**: a parser whose budgeted reparse halted before
  finishing. An edit that has not been parsed yet is not pending; it only
  needs a reparse, as today.
- A **budgeted attempt**: a reparse that may halt at the budget. It runs
  only from `treesit--pre-redisplay` and from idle slices (ticket 23).
- A **waiter**: any other caller that reaches `treesit_ensure_parsed`. It
  finishes the parse without a budget. This costs no more than today's
  synchronous reparse, and less when slices already did some of the work.

## Decisions

1. **Stale faces, not plain text.** While a parse is pending, redisplay
   shows the faces text already has. Nothing strips faces. The edited
   line keeps its old faces, marked `fontified nil` by
   `jit-lock-after-change` as today. Text that was never fontified shows
   unfontified, as under `jit-lock-defer-on-input` today.
2. **Defer the whole jit-lock chunk.** `jit-lock-function` treats "the
   current buffer's primary parser has a pending parse" as a reason to
   defer. It marks the chunk `fontified 'defer`, as the input deferral
   does. The check is independent of `jit-lock-defer-on-input`; turning
   the budget off is how budgeting is disabled. The chunk covers the
   tree-sitter font-lock function, `indent-bars` keywords, and
   `syntax-propertize` from `font-lock-default-fontify-region`. The
   predicate must be cheap C (a flag read), because redisplay calls it
   for each chunk. Its name and hook are for ticket 24.
3. **`treesit--pre-redisplay` makes the budgeted attempt.** It returns
   without marking anything when the attempt halts. It must **not**
   update `treesit--pre-redisplay-tick` then, or the next redisplay
   would skip the changed ranges. Whether a redisplay with no new edit
   spends another budget on a pending parse is part of slice scheduling
   (ticket 23).
4. **Every other reader waits.** `treesit-parser-root-node` and all the
   paths that reach it finish the parse. This includes `syntax-ppss`
   through `treesit--pre-syntax-ppss`, mode `syntax-propertize`
   functions, indentation (so RET under `electric-indent-mode`),
   navigation, imenu, and idle timers. No caller deliberately reads the
   edited old tree. Nodes made before completion stay valid until the
   new tree is installed, as they do today between an edit and a
   reparse. A stale-tree API would add semantics for small gains, since
   those callers run in commands and not in redisplay.
5. **`font-lock-ensure` waits.** Its fontify call reaches the root node.
   **`font-lock-flush`** only resets `fontified` and needs no change;
   the resulting redisplay defers as in 2.
6. **Completion marks the changes.** Whoever finishes the parse (an idle
   slice or a waiter) runs the parser's notifiers, as
   `treesit_ensure_parsed` does today. `treesit--font-lock-mark-ranges-to-fontify`
   then sets `fontified nil` on the changed ranges and moves
   `treesit--syntax-propertize-start`. This is today's code path, so
   there is no new invalidation logic.
7. **Completion re-arms the deferred chunks.** `jit-lock-deferred-fontify`
   runs only once per idle period. If it runs while the parse is still
   pending, redisplay defers the chunk again and nothing clears it until
   the next input. Two changes are needed:
   - `jit-lock-deferred-fontify` skips a buffer with a pending parse and
     keeps it in `jit-lock-defer-buffers`.
   - Completion from an idle slice runs deferred fontification for that
     buffer, and the redisplay after it applies the new faces. Ticket 23
     decides how that redisplay is scheduled.
8. **Scope.** Stage 2 budgets a buffer only when its parsers are the
   primary parser alone, with no included ranges. This is consistent with
   the map's out-of-scope list: `treesit-update-ranges` in the notifier
   would otherwise run on a partial state. python-ts-mode,
   typescript-ts-mode and tsx-ts-mode qualify.
9. **First parse stays synchronous in stage 2.** A buffer with no tree
   has no stale faces to show, so deferring would show plain text on
   open. Revisit this with the stage-2 numbers. This resolves the map's
   fog item as a recommendation, not a final answer.

## Known limits (inputs for the gate, ticket 25)

- A keystroke whose command itself reads the tree does not benefit. This
  covers RET with `electric-indent-mode`, `electric-pair-mode` on `"`
  (through `syntax-ppss`), and motion commands that call `syntax-ppss`.
  In the user's configuration only RET is affected. The `show-paren`
  timer waits after 0.125 s idle, normally after the slices have
  finished.
- `jit-lock-stealth-fontify` calls `jit-lock-fontify-now` directly, and
  would finish a pending parse unbudgeted at idle. Stealth is off by
  default, so this is left as is.
