# Decision: keep the change small in upstream files

2026-09-26. **Self-adopted, awaiting user confirmation.**

Evidence (nemesis `a6b93976e11`):
- **Upstream churn.** In the last six months there were 20 non-merge
  commits to `src/treesit.c`, 32 to `lisp/treesit.el` and 10 to
  `lisp/jit-lock.el`. All 10 jit-lock commits are the fork's own input
  deferral work.
- **Quiet hook points.** In the past year, no upstream commit touched
  `treesit_ensure_parsed`, `treesit_record_change_1`,
  `treesit_sync_visible_region` or `treesit_delete_parser`
  (`git log -L`), nor `src/treesit.h`. The upstream churn is elsewhere.
- **The parser timestamp is not an edit counter.** Despite its comment in
  `treesit.h`, `timestamp` increments only on a reparse
  (`treesit.c:1994`). Every text change sets `CHARS_MODIFF`
  (`insdel.c`); text property changes do not.
- **Fork precedent.** The rope feature adds plain-C files to the object
  list in `src/Makefile.in:485` and guards call sites with a configure
  option.

## Decisions

1. **New files own the logic.**
   - `src/treesit_budget.c` holds:
     - the progress callback;
     - the per-parser budget state;
     - the budgeted and continue primitives;
     - the pending predicate;
     - the stage-1 stats;
     - its own `syms_of_treesit_budget`.
   - `lisp/treesit-budget.el` holds:
     - the idle-slice timer and the pending list;
     - the staleness deadline;
     - the eligibility check (primary parser only, no included ranges);
     - the knobs, and the mode that turns budgeting on.

   The file name follows the fork's `rope_node.c` style.
2. **Hooks in upstream C files.** Each one is a line or a small block that
   calls into the new file:
   - **`treesit_ensure_parsed`**: `ts_parser_parse` becomes a call to
     `treesit_budget_parse`. A halted result returns nil before the tree
     is installed; that branch is a few lines. Stage 1 needs only the
     call.
   - **`treesit_delete_parser`**: one line to free the budget state.
   - **`struct Lisp_TS_Parser`** (`treesit.h`): one pointer field at the
     end, after the Lisp fields, so GC marking is unchanged. The new file
     owns the struct it points to.
   - **`syms_of_treesit`**: one line that calls
     `syms_of_treesit_budget`, so `emacs.c` is not touched.
   - **`src/Makefile.in`**: the object added to the list.
3. **No hooks on the edit paths.** The budget state stores the buffer's
   `CHARS_MODIFF`, the visible region and `last_set_ranges` when a parse
   halts. `treesit_budget_parse` compares them before resuming and calls
   `ts_parser_reset` if any differ. So `treesit_record_change_1`,
   `treesit_sync_visible_region` and
   `treesit-parser-set-included-ranges` stay untouched.
   - This is safe because nothing resumes between an edit and that check.
   - A spurious difference costs only a restart.
   - If stage 2's interleaved-edit ERT test finds a miss, add explicit
     notification lines at the `need_reparse = true` sites instead.
4. **The budget applies only inside the new primitive.** It sets a static
   budget, calls `treesit_ensure_parsed`, and clears the budget as soon as
   `treesit_budget_parse` returns. That happens before the notifiers run,
   so any nested reader is a waiter. The public
   `treesit-parser-changed-regions` keeps its meaning: it always finishes
   the parse.
5. **No configure option.** The file compiles whenever tree-sitter is
   configured. The `ts_parser_parse_with_options` path is used under
   `TREE_SITTER_LANGUAGE_VERSION >= 15` on systems other than Windows;
   elsewhere a stub calls `ts_parser_parse` and nothing ever halts. There
   is no `HAVE_MACGUI` guard, because the code is plain C. Budgeting is
   switched on and off by the Lisp mode at runtime, which also gives an
   A/B comparison without a second build. Whether it is on by default is
   decided at the stage-2 gate.
6. **Lisp hooks.**
   - **`treesit--pre-redisplay`** (in `treesit.el`, about 3 lines): call
     the autoloaded `treesit-budget--changed-regions`, which falls back to
     `treesit-parser-changed-regions` when budgeting is off or the buffer
     is not eligible. Do not advance the tick while a parse is pending.
   - **`jit-lock.el`**, already fork territory, gains two generic pieces
     with no tree-sitter knowledge:
     - a buffer-local predicate variable that defers fontification and
       makes `jit-lock-deferred-fontify` skip the buffer;
     - a small function that turns the current buffer's
       `fontified 'defer` marks back to nil.

     `treesit-budget.el` sets the first and calls the second.
   - `treesit-major-mode-setup` is not touched.
7. **AGENTS.md note.** Stage 1 adds a short "Budgeted tree-sitter
   parsing" note to AGENTS.md, which lists the hooks above. When a GNU
   sync conflicts in these functions, take upstream's version, re-apply
   the hook lines, and build, since the new file depends on the parser
   struct and on `treesit_ensure_parsed`'s locals. That note is part of
   stage 1, which is when the hooks exist; this ticket only fixes what
   it says.

## Expected upstream diff

About 15 lines in `treesit.c`, 2 in `treesit.h`, 1 in `Makefile.in` and
3 in `treesit.el`, plus fork-local lines in `jit-lock.el`. Stage 1 alone
touches `treesit.c` (about 3 lines), `treesit.h`, `Makefile.in` and the
new C file.
